# 第 2 课：板级配置三件套

目标：改板时知道动哪三个文件，以及 PARTUUID 为什么要对齐。

---

## 1. 三件套

| # | 作用 | 本板路径 |
|---|------|----------|
| ① | SDK 板级总开关 | `device/rockchip/rv1126b/OK1126B_S_buildroot_defconfig` |
| ② | 分区表 | `device/rockchip/rv1126b/parameter.txt` |
| ③ | 硬件描述（设备树） | `kernel-6.1/arch/arm64/boot/dts/rockchip/OK1126B-S-linux.dts` |

练习沙盒：

- `OK1126B_PRACTICE_buildroot_defconfig`（`RK_KERNEL_DTS_NAME="OK1126B-practice-linux"`）
- `OK1126B-practice-linux.dts`

---

## 2. ① defconfig = 选型，不描述引脚

| 变量 | 落到哪里 |
|------|----------|
| `RK_UBOOT_CFG` | `u-boot/configs/OK1126B-S_defconfig` |
| `RK_KERNEL_CFG` | `kernel-6.1/arch/arm64/configs/...` |
| `RK_KERNEL_DTS_NAME` | `.../dts/rockchip/<name>.dts` |
| `RK_BUILDROOT_BASE_CFG` | Buildroot：`rockchip_ok1126b-s_defconfig` |
| `RK_WIFIBT_CHIP` | WiFi/BT 配套 |

改 WiFi 芯片型号 → 动 **defconfig**。  
改某个 GPIO 脚 → 动 **DTS**（通常不是 defconfig）。

---

## 3. ② parameter.txt = Flash 怎么切

`CMDLINE` 中的分区顺序示例：

```text
uboot → env → misc → boot → recovery → backup → userdata → rootfs
```

注意：这里**没有**直接写 RAM/FLASH 总容量；写的是各分区大小与偏移。

---

## 4. ③ DTS = 板子硬件长什么样

主文件往往很薄，内容在 include 里：

```dts
#include "OK1126B-S-common.dtsi"
#include "OK1126B-S-camera.dtsi"
#include "OK1126B-S-display.dtsi"

/ {
	model = "Forlinx OK1126B-S Board";
	compatible = "rockchip,rv1126b-evb1-v10", "rockchip,rv1126b";
	chosen {
		bootargs = "... root=PARTUUID=614e0000-0000 ...";
	};
};
```

| 文件 | 职责 |
|------|------|
| `*-common.dtsi` | CPU、内存、UART、eMMC、网络等 |
| `*-camera.dtsi` | 摄像头 |
| `*-display.dtsi` | 显示 |

---

## 5. PARTUUID 为什么必须对齐

```text
parameter.txt:  uuid:rootfs=614e0000-0000-4b53-8000-1d28000054a9
        ↓ 烧录写入分区表
内核 bootargs:  root=PARTUUID=614e0000-0000
        ↓ 按 UUID 找分区
挂载该分区为 /
```

两边不一致 → 常卡在 `Waiting for root device`。  
对齐的是「找哪个分区」，不是随便一个内存地址。
