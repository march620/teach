## 1. Rockit 是什么

**Rockit = Rockchip 多媒体中间件**：用户态拼「采集 → 处理 → 编码/显示/音频」。

| 接口 | 特点 | 典型场景 |
|------|------|----------|
| **TGI** | 配置文件搭较固定 Pipeline | UVC / UAC |
| **MPI** | 模块化 API，可 Bind | **IPC / NVR**（本课重点） |

OK1126B / IPC 默认学 **MPI**。

## 3. 主要模块

| 模块 | 头文件 | 作用 |
|------|--------|------|
| SYS | `rk_mpi_sys.h` | Init、**Bind**、MMZ |
| MB | `rk_mpi_mb.h` | 媒体缓冲 |
| VI | `rk_mpi_vi.h` | 视频输入 |
| VPSS | `rk_mpi_vpss.h` | 缩放/多路 |
| VENC / VDEC | `rk_mpi_venc.h` / `vdec` | 编码 / 解码 |
| VO | `rk_mpi_vo.h` | 显示 |
| RGN | `rk_mpi_rgn.h` | OSD |
| AI/AO/AENC/ADEC | 对应头文件 | 音频 |

底层编码常落到 **MPP**；画质在 **RKAIQ**。

## 4. 通道 + Bind

```c
RK_MPI_SYS_Init();
// 配置 Enable VI、Create VENC …
RK_MPI_SYS_Bind(&src_vi_chn, &dst_venc_chn);  // 自动送帧
RK_MPI_VENC_GetStream(...);
```

也可手动：`VI_GetChnFrame` → `VENC_SendFrame` → `GetStream`。

## 5. 读 `test_mpi_vi.cpp` 的正确姿势

文件很长（约 1800 行），是多模式合集。先看 `TEST_VI_MODE_E`，再跟一条路径。

### `test_vi_init`：打开 VI

```text
Dev → Pipe → Chn → EnableChn
```

结束后：**可以从该 VI 通道出 YUV 帧**（不是「多了判断」）。

### `test_vi_bind_vo_loop`：VI → VO 预览

```text
test_vi_init → create_vo → Bind(VI→VO) → EnableChn(VO)
→ 循环里几乎只 usleep（Bind 已在后台送帧）
→ UnBind / 关闭
```

`test_vi_init` **不会**把输入转到输出；**Bind** 才负责转向。

### 编码应走 VENC，不是 VDEC

```text
要存文件/推流：Bind VI → VENC，再 GetStream
不要用 VDEC（那是解码）
对应约 -m 1 的 bind venc 路径，不是 vdec_bind_vo
```

本文件辅助函数：`create_venc` / `create_vpss` / `create_rgn` = 建编码/VPSS/OSD。  
`RK_MPI_SYS_CreateMB` = 申请媒体内存，不是建 VI。

## 课后要点

1. TGI 偏固定管道；MPI 用 API 更灵活。  
2. `Bind` = 自动送帧。  
3. init 完 = 能从 VI 出帧；Bind 完 = 帧自动到下游。
