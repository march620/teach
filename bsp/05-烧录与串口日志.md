# 第 5 课：烧录与串口日志

目标：会按改动范围选择刷整包还是单分区，会用串口对照启动链排错。

---

## 1. 刷之前确认镜像

改完 DTS/内核：

```bash
grep RK_KERNEL_DTS_NAME output/.config
ls -l kernel-6.1/arch/arm64/boot/dts/rockchip/OK1126B-practice-linux.dtb
ls -l output/firmware/boot.img
```

只改 DTS → **`make kernel` 后只刷 boot** 即可（不必重刷 rootfs/uboot/parameter）。

---

## 2. 下载模式

| 模式 | 用途 |
|------|------|
| MaskROM | 空片或抢救 |
| Loader | 日常 USB 升级 |

以飞凌说明书按键/跳线为准。PC 应识别 Rockusb 类设备。

**WSL2 注意：** USB 烧录常需在 Windows 侧工具，或用 `usbipd` 把设备挂进 WSL。SDK 脚本默认用：

```text
tools/linux/Linux_Upgrade_Tool/.../upgrade_tool
./rkflash.sh
```

---

## 3. 常用烧录方式

```bash
./rkflash.sh update    # 整包 update.img
./rkflash.sh boot      # 只写 boot 分区（改 DTS/内核首选）
./rkflash.sh rootfs    # 只写根文件系统
./rkflash.sh uboot
./rkflash.sh all       # 按分区逐个刷
```

| 场景 | 建议 |
|------|------|
| 只改 DTS/内核 | `make kernel` → `rkflash.sh boot` |
| 改了用户程序/overlay | `make rootfs` → `rkflash.sh rootfs` |
| 大改或首次量产刷机 | `update.img` 整包 |

---

## 4. 串口参数

本板 DTS `chosen` / fiq_debugger：

- 波特率 **115200**
- `console=ttyFIQ0`

接调试 UART（丝印 DEBUG/UART），例如：

```bash
sudo minicom -D /dev/ttyUSB0 -b 115200
```

期望日志顺序：

```text
DDR/Loader → U-Boot → Kernel → 挂 rootfs → 登录提示符
```

板上验证 practice DTB：

```bash
cat /proc/device-tree/model
# 期望: OK1126B Practice Board

ls /sys/class/leds/
# 脚选对时可能有 practice-led；没有不一定代表 DTB 错
```

---

## 5. 常见卡点

| 现象 | 多半原因 |
|------|----------|
| 完全无打印 | 波特率/接线/串口选错 |
| 停在 Loader/U-Boot | boot 坏或 FIT 不对 |
| `Waiting for root device` | PARTUUID / 分区表不一致 |
| 内核起不来用户态 | rootfs 镜像/分区问题 |

---

## 课后练习

1. 只改 DTS，刷整包还是只刷 boot？为什么？
2. 有板时：刷 boot 后看串口，并执行 `cat /proc/device-tree/model`。
3. 无板时：至少能口述 MaskROM→…→Rootfs，以及 `rkflash.sh boot` 的用途。
